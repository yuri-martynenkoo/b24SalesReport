# Материалы для проверки — «Аналитика продаж»

**Работающее приложение:** https://app-916c4e0a9320.vibecode.bitrix24.tech (версия исходников `v9`). **Исходный код без секретов:** https://github.com/yuri-martynenkoo/b24SalesReport. Приложение опубликовано в Битрикс24 как «Дашборд продаж»; прямой переход без авторизованной сессии портала может вернуть `401`, поэтому проверять его следует из раздела «Приложения» портала.

**Назначение и сценарии.** Дашборд показывает сделки CRM в пределах прав открывшего его сотрудника. По выбранному направлению, ответственному и периоду создания он строит сводку количества и суммы по стадиям (`stageId`), выводит отдельные KPI открытых и выигранных сделок и средний чек выигранных. Фильтр ответственного по умолчанию выключен; список формируется по сделкам выбранного направления и периода. Суммы разных валют не смешиваются. Ниже отображаются 15 последних по созданию сделок с названием-ссылкой на карточку, суммой, направлением, стадией, ответственным и подразделением; строки можно сортировать. Фильтры применяются без отдельной кнопки. Выборка более 5 000 сделок загружается курсором по 500 записей до конца, без обрезания итогов.

**Скоупы.** `crm` нужен для сделок, направлений и стадий; `user` — для ФИО ответственных (`user_basic` не даёт доступ к используемому `/v1/users`); `department` — для названий отделов; `placement` — для публикации/встраивания приложения; `vibe:infra` — для деплоя и резервного поиска ФИО при отсутствии `user`. Текущий ключ платформы имеет также дополнительные скоупы, не используемые кодом отчёта; их следует сократить при плановой перевыпуске.

**Известные ограничения.** Фильтр относится к *дате создания*: выигранные сделки — созданные в период и выигранные сейчас, а не закрытые в период; открытые сделки старше выбранного периода исключены. Границы дат считаются в UTC. При очень большой выборке загрузка может быть долгой или упереться в лимит API; тест с 5 201 сделкой выполнен на имитации API, не на реальном портале. Справочники сотрудников и отделов запрашиваются максимум по 5 000 записей, поэтому в большой организации часть ФИО/подразделений может отсутствовать.

**Порядок проверки.** Авторизуйтесь в портале Битрикс24 под сотрудником с доступом к CRM и откройте «Дашборд продаж» из «Приложений». Выберите направление, убедитесь, что список ответственных обновился, затем выберите сотрудника и быстрый или произвольный период: данные должны обновляться сразу. Сверьте KPI и стадии с CRM при тех же правах и датах создания; проверьте сортировку и переход по названию сделки. Для проверки кода выполните `npm run check` в корне репозитория. Ключи проверяющему не требуются и в Git не включены.
