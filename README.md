# Аналитика продаж для Битрикс24

Встраиваемый VibeCode-дашборд по сделкам CRM. Приложение работает через Black Hole Gateway от лица сотрудника, который открыл пункт меню в Битрикс24.

- Приложение: https://app-916c4e0a9320.vibecode.bitrix24.tech
- Исходный код: https://github.com/yuri-martynenkoo/b24SalesReport
- Краткие [материалы для проверки](SUBMISSION.md)
- Действующая версия исходников VibeCode: `v8` (16.10.2026)

## Возможности

- количество и сумма сделок по каждой стадии (`stageId`);
- отдельные показатели суммы и количества открытых и выигранных сделок, средний чек выигранных;
- 15 последних по дате создания сделок со ссылками на карточки, направлением, стадией, ФИО ответственного и его подразделением; сортировка столбцов меняет порядок только этих 15 сделок;
- фильтры по направлению и дате создания: 7/30/90 дней, текущий квартал или произвольный диапазон; быстрый период применяется по нажатию, направление и дата — после подтверждения выбора, без кнопки «Применить»;
- постраничная загрузка всех сделок выбранного периода курсором `id` по 500 записей, без ограничения итогов первыми 5 000; при ошибке страницы неполный отчёт не показывается;
- корректные итоги для нескольких валют;
- responsive-интерфейс, состояния загрузки, ошибки и пустой выбор.

Все показатели, стадии и последние сделки относятся к **одному выбранному периоду создания** и направлению. «Выигранные за период» — это сделки, созданные в период и находящиеся в выигранной стадии сейчас; это не показатель по дате закрытия. Открытые сделки, созданные до начала периода, также не входят в KPI. Суммы группируются по направлению и `stageId`; суммы разных валют показываются отдельно.

## Безопасность и авторизация

Ключ `vibe_app_…` хранится только в секрете/переменной окружения `vibe_app_local` (также поддерживается alias `VIBE_APP_KEY`). Значение не попадает в HTML, JavaScript браузера или Git; `.env` исключён из репозитория. Gateway передаёт серверу `X-Vibe-Authorization`, а сервер обращается к VibeCode с ключом приложения в `X-Api-Key` и сессией текущего пользователя в `Authorization: Bearer`. Доступны только те сделки, которые сотрудник вправе читать в Битрикс24.

Для решения нужны следующие скоупы:

| Скоуп | Назначение |
| --- | --- |
| `crm` | Чтение сделок, направлений и стадий. |
| `user` | ФИО ответственных из `/v1/users`; `user_basic` для этого маршрута недостаточен. |
| `department` | Названия подразделений ответственных. |
| `placement` | Публикация и открытие приложения внутри Битрикс24. Дополнительный `LEFT_MENU` в действующей установке не создаётся. |
| `vibe:infra` | Деплой на Black Hole server и резервный поиск ФИО через справочник сервера, если `user` недоступен. |

Текущий выданный ключ содержит также дополнительные скоупы платформы, которые код отчёта не использует; их можно сократить при плановой перевыпуске ключа и повторной авторизации. См. документацию VibeCode: [сделки](https://vibecode.bitrix24.tech/docs/entities/deals/list), [сотрудники](https://vibecode.bitrix24.tech/docs/entities/users), [отделы](https://vibecode.bitrix24.tech/docs/entities/departments/list), [места встраивания](https://vibecode.bitrix24.tech/docs/apps/placements), [инфраструктура](https://vibecode.bitrix24.tech/docs/infra).

## Известные ограничения

- Границы выбранных дат передаются в API как `00:00:00Z`—`23:59:59.999Z` (UTC), а не в часовом поясе портала.
- Очень широкий период требует последовательной загрузки всех страниц: время ответа и расход API-лимита растут с числом сделок. Более 5 000 сделок проверены автоматическим тестом с 5 201 записью, но не подтверждены на реальном портале с такой выборкой.
- Списки сотрудников и отделов запрашиваются максимум по 5 000 записей каждый; в очень большой организации ФИО или подразделение отдельных ответственных могут быть недоступны.
- Прямая проверка URL без сессии портала может получить `401` от Gateway. Успех `/health` подтверждает запуск сервиса, но не доступ конкретного сотрудника к CRM.

## Локальная проверка

Требуется Node.js 20 или новее, внешних npm-зависимостей нет.

```bash
npm run check
```

Команда проверяет синтаксис и запускает тесты, включая обход 5 201 сделки и построение ссылки на карточку. Для реальных данных приложение должно быть открыто из Битрикс24: локальный браузер не получает защищённый заголовок Gateway.

## Развёртывание VibeCode

1. Создайте OAuth-приложение VibeCode с перечисленными скоупами и сохраните `vibe_app_…` как серверный секрет `vibe_app_local`. Не включайте ключ в репозиторий или архив. Вызовы платформы отправляйте с ключом в `X-Api-Key`; `Authorization` используется только для пользовательской сессии.
2. Разверните архив корня проекта на Black Hole server: `runtime: node20`, `port: 3000`, `start: node src/server.js`, `healthPath: /health`, `hardening: auto`. Для повторного деплоя на действующий сервер сохраняйте `serviceName: sales-report` и `.env` (`preserveEnv: true`), а также указывайте фактическую базовую версию исходников. См. [Deploy API](https://vibecode.bitrix24.tech/docs/infra/deploy/deploy).
3. Опубликуйте приложение с URL сервера и авторизуйте его на портале. В действующей установке приложение уже опубликовано; не добавляйте второй `LEFT_MENU`, чтобы не получить два одноимённых пункта.
4. Проверьте успешный `/health` от сервиса и откройте «Дашборд продаж» в Битрикс24 под сотрудником с доступом к CRM. Выберите направление и период, сравните KPI и стадии с CRM, откройте карточку сделки по названию.
