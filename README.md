# Аналитика продаж для Битрикс24

Встраиваемый VibeCode-дашборд по сделкам CRM. Приложение работает через Black Hole Gateway от лица сотрудника, который открыл пункт меню в Битрикс24.

## Возможности

- количество и сумма сделок по каждой стадии (`stageId`);
- сумма открытых сделок, число выигранных и средний чек выигранных;
- 15 последних сделок со стадией и ответственным;
- фильтр по дате создания: 7/30/90 дней, текущий квартал или произвольный диапазон;
- корректные итоги для нескольких валют;
- responsive-интерфейс, состояния загрузки, ошибки и пустой выбор.

## Безопасность и авторизация

Ключ `vibe_app_…` хранится только в секрете/переменной окружения `vibe_app_local` (также поддерживается alias `VIBE_APP_KEY`). Управляющий ключ хранится в секрете `vibe_api`. Значения не попадают в HTML, JavaScript браузера или Git. Gateway передаёт серверу `X-Vibe-Authorization`, а сервер проксирует запросы к VibeCode API с сессией текущего пользователя. Доступны только те сделки, которые сотрудник вправе читать в Битрикс24.

## Локальная проверка

```bash
npm test
npm run check
```

Для реальных данных приложение должно быть открыто через placement VibeCode: локальный браузер не получает защищённый заголовок Gateway.

## Развёртывание VibeCode

1. Создайте OAuth-приложение с ключом `vibe_app_…` и скоупами `crm`, `user`, `placement`, `vibe:infra`.
2. Создайте Black Hole server и разверните архив репозитория. Порт — `3000`, стартовая команда — `npm start`.
3. Передайте значение секрета `vibe_app_local` в одноимённую переменную `env` деплоя. Управляющие запросы к VibeCode выполняйте значением секрета `vibe_api` исключительно через `X-Api-Key`.
4. Задайте `appUrl`, завершите OAuth-авторизацию и опубликуйте placement `LEFT_MENU` с названием «Аналитика продаж».

Проверка здоровья: `GET /health` → `{ "ok": true }`.
